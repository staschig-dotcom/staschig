# Еженедельное скачивание финотчётов WB / Ozon / ЯМ

Агент: `.claude/agents/mp-finreport-downloader.md`. Работает **только на вашем Windows-ПК**: Chrome с расширением Claude in Chrome, залогиненный аккаунт, диск D:.

## 1. Установка (один раз)

1. Скопировать агента в пользовательскую папку, чтобы он был виден из любого проекта:
   `%USERPROFILE%\.claude\agents\mp-finreport-downloader.md`
2. Создать `D:\Еженедельные оперативки\_агент\` и положить туда `clients.json` и `move-download.ps1`.
3. `clients.json` уже заполнен реальными кабинетами (юрлицо, магазин, ИНН, id продавца). Агент сверяет активный кабинет с ними и при несовпадении ничего не скачивает (`WRONG_CABINET`).
4. Проверить точные имена инструментов Chrome: в Claude Code `/mcp` → claude-in-chrome. Если имена отличаются от строки `tools:` в агенте — поправить.
5. Разрешить без подтверждений запуск помощника (`.claude/settings.json`):
   ```json
   { "permissions": { "allow": [
     "Bash(powershell.exe -NoProfile -ExecutionPolicy Bypass -File \"D:\\Еженедельные оперативки\\_агент\\move-download.ps1\":*)",
     "mcp__claude-in-chrome__*"
   ] } }
   ```

## 2. Тестовый прогон (один клиент)

Рекомендую **Даминдарову**: один кабинет, только Ozon — минимум переменных.

```
claude --chrome
> Используй агента mp-finreport-downloader. Тестовый прогон только для клиента «Даминдарова».
```

Критерии «нормального прогона», прежде чем включать остальных и расписание:
- файл в `D:\Еженедельные оперативки\<понедельник>\Даминдарова\`, открывается, период = прошлая неделя;
- в файле именно её товары/юрлицо (проверить глазами — это главный риск);
- лог `_лог_скачивания.md` и `_статус_скачивания.json` заполнены;
- нарочно разлогиниться в одном ЛК и прогнать ещё раз → должен быть `SESSION_EXPIRED` и продолжение, а не зависание.

Затем то же на «Караматов + Аббасова» (проверяет переключение между двумя кабинетами WB одного клиента и Ozon).

## 3. Расписание (пилот пройден 11.10.2026)

Облачные расписания claude.ai не подходят: им недоступны ваш Chrome и диск D:. Запуск через Планировщик заданий Windows.

1. Положить `run-weekly.ps1` в `D:\Еженедельные оперативки\_агент\`.
2. Один раз вручную проверить запуск без участия: в PowerShell
   `powershell -NoProfile -ExecutionPolicy Bypass -File "D:\Еженедельные оперативки\_агент\run-weekly.ps1" -Retry`
   Если Claude остановится на запросе разрешения — добавить разрешения из шага 5 установки и повторить. В `-p` режиме спросить некого, прогон просто встанет.
3. Создать два задания (PowerShell от вашего пользователя):
   ```
   schtasks /Create /TN "МП финотчёты - понедельник" /SC WEEKLY /D MON /ST 13:45 /IT /TR "powershell.exe -NoProfile -ExecutionPolicy Bypass -File \"D:\Еженедельные оперативки\_агент\run-weekly.ps1\""
   schtasks /Create /TN "МП финотчёты - вторник повтор" /SC WEEKLY /D TUE /ST 09:45 /IT /TR "powershell.exe -NoProfile -ExecutionPolicy Bypass -File \"D:\Еженедельные оперативки\_агент\run-weekly.ps1\" -Retry"
   ```
   `/IT` — запуск только когда вы вошли в Windows: Chrome с вашими сессиями есть только в вашем сеансе.

Почему так: WB формирует недельный отчёт в понедельник, утром его часто ещё нет. Понедельник 13:45 — основной прогон, вторник 9:45 — добор только того, что было `NOT_READY`/ошибкой.

Условия работы: ПК включён и не спит, вы залогинены в Windows, Chrome открыт с расширением, сессии WB/Ozon/ЯМ живые. Если хоть одно не выполнено — прогон не случится или даст `SESSION_EXPIRED`; это видно в `_лог_скачивания.md` и в `_агент\scheduler.log`.

## Статусы в логе

| Статус | Что делать руками |
|---|---|
| SESSION_EXPIRED | перелогиниться в ЛК |
| CAPTCHA | открыть ЛК, пройти капчу, перезапустить по клиенту |
| WRONG_CABINET | проверить `cabinet_match` / доступ к кабинету |
| NOT_READY | отчёт ещё не сформирован — повторить позже |
| UI_NOT_FOUND | маркетплейс поменял интерфейс — обновить `hint` в реестре |
| PAGE_TIMEOUT / DOWNLOAD_TIMEOUT / CLIENT_TIMEOUT | повторить по клиенту |
